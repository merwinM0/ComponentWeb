# SVG 组件背景：折角面板（设计提案，未接入工作台）

设计稿：[svg-panel.svg](./svg-panel.svg)。参考项目现有工作台的深色底、浅蓝强调、1px 细边与方角语言；不引入渐变、发光、动画或外部素材。第一款用于信息卡片、检索面板和小型数据容器，而非将文字和输入框一起画进 SVG。

## 1. 视觉设计

- 设计尺寸 360×240px，对应 30×20 个 12px 网格。
- 左上凸起标题签，右上与底部折角；标题签之外的顶部和缺角保持透明，不用矩形底色补满。
- 默认底色 `#101d29`、边线 `#48657d`、强调线 `#8bd5ff`；接入时应映射到组件背景 / 边框 / 强调色属性，而非跟随页面主题强制改色。
- SVG 只有装饰背景，不包含正文、标题文字或交互。标题用真实 HTML 放在标题区，正文和组件放在内容区；可编辑、可选中、可访问。
- 当前文件是固定尺寸设计稿，不代表已经支持任意宽高自适应。

## 2. 必须区分的几何范围

| 范围 | 这款面板的定义 | 用途 |
| --- | --- | --- |
| 外部占位 / 变换框 | x=0、y=0、W=360、H=240 | 网格位置、W/H、缩放手柄、外部对齐、第一阶段同级碰撞 |
| 视觉轮廓 | SVG 主 path，含透明缺角 | 绘制背景和边线；不能用外接矩形底色覆盖缺角 |
| 标题区 | x=24、y=4、W=96、H=20 | 独立可选标题，不作为正文流的一部分；过长省略或提示，不撑开背景 |
| 正文安全区 | x=24、y=48、W=312、H=168 | 自由 / Flex / Grid 的真正布局父级及子项边界 |
| 装饰溢出 | 本稿为 0 | 以后若有阴影、光晕或突出装饰，单独记录，不扩大布局占位 |

安全区上 / 右 / 下 / 左分别预留 48 / 24 / 24 / 24px，属于背景模板固有的几何预留，不是新增一套可调外边距。用户原有 padding 在安全区内再应用一次；gap 继续只作用于子项之间。

**不以不透明像素包围盒代替占位框，不把内容包围盒当作背景尺寸，也不将 SVG viewBox 留白误认为实际背景。** 本稿可见轮廓的极值紧贴设计框，避免隐含的大幅留白。编辑时应分别显示外层选框和内容安全区虚线，预览时隐藏辅助线。

## 3. 内部仍能沿用现有布局

建议作为 `layout.container` 的一种背景皮肤，而不是另外创建只有图像、没有子树能力的 SVG 素材类型：

```text
容器外部占位框（现有位置和显示宽高）
└─ 内部设计坐标系（现有 design.width / height）
   ├─ SVG 背景：绝对定位、aria-hidden、pointer-events:none
   ├─ HTML 标题区：独立定位
   └─ 安全区 DOM：定位偏移 → 现有 padding → 子项 slot
      └─ 自由 / Flex / Grid、子项伸缩、跨格、内容高度
```

子项坐标原点应位于「安全区 + 用户 padding + 必要边线预留」之后，而不是整个 SVG 的左上角。子项内容自适应高度仍服从安全区约束，不撑大父面板。必要时滚动或拒绝越界；不能只用 clip-path 把放不下的文字裁掉来掩盖布局错误。

第一版使用一个保守的矩形正文安全区，避免文字和控件进入折角。SVG 不会让 CSS Flex / Grid 自动沿凹凸边缘排版；以后若要环形、L 形或多个洞口的背景，应显式定义多个内容区域，而不是从任意 path 自动猜布局。

## 4. 选中、命中与碰撞

- 选择框、缩放手柄仍使用外接矩形，保持现有键盘、框选、对齐和历史行为，不强行把手柄贴到每条斜边。
- 是否把透明缺角的点击穿透给下层对象，是独立的命中策略。第一版可继续按占位框选择；需要精确轮廓命中时再对指针做 path 测试，不影响键盘 / 层级面板选择。
- 拖入背景面板的子项必须进入正文安全区，不把标题签或透明缺角当成有效落点。
- 第一版碰撞仍按外部占位框检查；这不等于已经支持相邻不规则形状互相嵌合。若以后要缺角互嵌 / 真正无缝拼接，需要独立实现轮廓碰撞或明确的装饰溢出规则，不能直接关闭所有碰撞。

## 5. 缩放不能只拉伸一张 SVG

现有模型已分离容器内部设计尺寸与外部显示尺寸，应继续沿用：

1. 修改内部设计尺寸：按新宽高重算背景 path 和安全区，折角参数保留为内部设计像素；同步校验最小尺寸与子项边界。
2. 修改外部显示尺寸：背景、标题、内容和安全区使用同一变换，不能只放大选框或只缩放 SVG。
3. 若要求折角不变形，外部缩放应锁定宽高比；现有 `displayScale` 允许 X/Y 不同倍率，不能声称当前就会自动保持折角角度。
4. 不建议直接使用 `preserveAspectRatio="none"` 拉伸任意背景；它会拉坏折角和边线。等比 contain 又可能造成留白。第一版优先用参数化 path，而非试图为所有外部 SVG 自动生成九宫格拉伸。

正式实现应给此皮肤声明最小内部尺寸，并校验标题区与正文安全区不交叉、内容能放下。不能沿用普通空容器的 24×24px 最小设计空间。

## 6. 对现有代码的影响

目前 `components/container/index.ts` 的矩形背景与内容共用 `.container-surface`，`core/tree.ts` 的 `contentSize`、`core/edit-region.ts` 的 `regionOf` 都只计算统一 padding / 边框，不知道不规则背景的安全区。

接入时应新增一个共用的「容器内容区域」几何函数，同时供以下位置使用，避免渲染和校验各算一套：

- 背景模板元数据、安全区 DOM 定位和尺寸。
- 自由布局可用宽高、添加时找空位与位置字段范围。
- 拖放目标与坐标换算、嵌套缩放、框选 / 换层 / 解散。
- 原位编辑框边界与散件组装。
- 存档校验、组合快照、复制、撤销重做和旧布局默认值。

可保存皮肤 ID 与少量经过验证的参数，不需要把任意 SVG 字符串写进每个节点。旧容器没有皮肤字段时，继续使用现有矩形区域，保持旧数据不变。

现有 HTML + CSS 导入明确拒绝 SVG，这个设计稿不能直接粘贴进当前导入弹窗。第一阶段先接入可信的内置背景；以后如需 SVG 导入，要单独设计安全白名单，拒绝脚本、事件、foreignObject、外部链接 / 资源等，不应直接放开任意 SVG。

## 7. 建议实施顺序

1. 确认本稿的视觉方向和「外框 / 轮廓 / 安全区」划分。
2. 增加共用内容区域模型，先确保旧矩形容器全部回归通过。
3. 将这款背景作为容器皮肤接入，增加编辑态安全区辅助线。
4. 覆盖自由 / Flex / Grid、字体与高度变化、嵌套缩放、边界拒绝、保存刷新和历史回归。
5. 后续再扩展背景库、安全 SVG 导入、多内容区、精确轮廓命中及互嵌碰撞。
